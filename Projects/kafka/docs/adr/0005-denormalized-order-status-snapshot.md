# OrderStatus snapshots Order contents instead of referencing OrderPlacedEvent

`OrderStatus` stores its own copy of `items` and `totalAmount`, captured once when OrderStatusService first consumes `OrderPlacedEvent` for a given `orderId`, rather than requiring a second lookup against the original event. This is a deliberate denormalization: the same data exists in two places (`OrderPlacedEvent` and `OrderStatus`), but it means `GET /orders/{id}` and the SignalR push to the Blazor UI are single reads against one in-memory record, with no join or replay-and-merge step. Since `OrderStatus` is a disposable materialized view already rebuilt from the log on restart (see [ADR 0002](./0002-in-memory-materialized-view.md)), there is no update-anomaly risk from the duplication — the snapshot is simply recomputed correctly every time the view is rebuilt.
