# Consumers log and skip on an unhandled processing error

If a service throws while processing a message due to a genuine bug (not a simulated business failure like a declined payment), it logs the exception and commits the offset anyway, moving on to the next message — it does not retry, crash, or route the message to a dead-letter topic. This is consistent with dead-letter topics/retry being an explicit stretch goal ([PROJECT.md](../../PROJECT.md)) rather than in-scope for v1. The cost is that a real bug silently drops the affected Order's event with no record of the failure beyond the log line; we accept this because a crash loop or a blocked partition would be far more disruptive to a live demo than a single skipped message, and this project does not need production-grade failure recovery to make its point about Kafka concepts.
